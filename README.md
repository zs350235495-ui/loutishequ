## 🛠️ 双软路由高可用拓扑与流量调度实战 (Network Engineering)

在大规模并发与多设备场景下，合理配置主旁路由或双软路由协同架构，能够有效降低主网关负载并彻底解决 DNS 污染与 WebRTC 泄露：

### 1. iKuai（主路由）+ 旁路由（OpenWrt/Linux 网关）流量镜像与分流模型
```text
           [外部千兆光纤接入 (WAN)]
                      │
                      ▼
            ┌──────────────────┐
            │ iKuai 硬件主路由  │ ◄─── (负责 PPPoE 拨号、DHCP 分配、NAT 高速转发)
            └─────────┬────────┘
                      │ 局域网主干 (LAN: 192.168.1.1)
         ┌────────────┴────────────┐
         ▼                         ▼
┌──────────────────┐      ┌──────────────────┐
│  常规局域网设备  │      │  旁路网关设备    │ (IP: 192.168.1.2)
│ (网关指向 .1)    │      │ (TUN/TPROXY 内核)│ ◄─── (负责境外流量加密封装与分流调度)
└──────────────────┘      └────────┬─────────┘
                                   │ 流量劫持
                                   ▼
                         [境外流量定向加速传输]
```

#### 分流核心设计原则：
* **主路由职责解耦**：iKuai 专注于千兆 PPPoE 硬件加速、NAT 端口映射与多拨聚合，旁路网关处理 CPU 密集型流量加解密与策略路由匹配，保障主内网高稳定性；
* **单臂旁路避坑**：旁路由网卡关闭 DHCP 服务，关闭 `ip6tables` 避免 IPv6 流量无感绕过旁路产生泄露；
* **TPROXY vs TUN**：在 Linux 内核层采用 TPROXY（透明代理）保留原始源 IP 地址，配合 `mangle` 表规避连接追踪（conntrack）表膨胀导致的丢包。

### 2. MosDNS 境内外双分流与防污染流水线
```text
[本地设备发起 DNS 查询]
        │
        ▼
┌──────────────────┐
│ MosDNS 解析引擎  │ ◄─── 监听本地 192.168.1.2:53
└───────┬──────────┘
        │
        ├─► [国内域名/GeoIP:CN] ──► 119.29.29.29 / 223.5.5.5 ──► 秒级直连响应
        │
        └─► [非CN/广告过滤/未命中] ──► 远程加密隧道 / Fake-IP ──► 杜绝 DNS 投毒
```

## 🔬 千兆抓包观测模型与晚高峰抖动离散度分析 (Telemetry)

实验室采用真实电信、联通、移动千兆物理接入环境，构建自动化探测与抓包审计平台：

### 1. 晚高峰 QoS 丢包与抖动离散度计算
端到端网络质量的关键不在于非高峰期的基准时延，而在于晚高峰（20:00 - 23:00）骨干网拥塞时的时延方差与 TCP 拥塞控制反应：

$$\sigma = \sqrt{\frac{1}{N} \sum_{i=1}^{N} (RTT_i - \overline{RTT})^2}$$

* **优质 IPLC 专线**：抖动方差 $\sigma < 1.5\text{ ms}$，无拥塞重传，丢包率 $< 0.1\%$；
* **普通公网中转**：高峰期 $\sigma > 25\text{ ms}$，发生间歇性 Tail-drop 丢包，需要借助 BBR 拥塞控制算法的主动抗丢包能力保持吞吐。

### 2. WebRTC 真实 IP 泄露防护原理
当客户端通过代理访问时，部分浏览器可能通过 STUN 请求在 UDP 通道中发送真实本地与公网 IP。
* **防护方案**：在代理客户端中启用严格的 Fake-IP 模式，将所有 `*.stun.*` 和 UDP 3478 请求强制重定向至透明代理环回接口，或在系统防火墙级别屏蔽未受代理接管的直接 UDP 出站流量。
